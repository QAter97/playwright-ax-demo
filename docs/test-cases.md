## 관찰·리뷰 및 구현 연결

- TC-LGN-001은 2026-11-18 Chromium PC(1280×720)·Pixel 7 에뮬레이션에서 직접 확인했다. 두 환경 모두 HTTP 200, Username(text)·Password(password)·Login(submit)을 확인했다. 사용자 진행 승인에 따라 P0 샘플로 구현한다. 후속 TC는 관찰·리뷰 대기다.
- P0 리뷰 대상은 TC-LGN-001이다. P2 리뷰와 구현은 완료했으며 P3 TC는 해당 Phase에서 관찰과 리뷰를 완료한다.
- 핵심 구매 경로에는 @smoke와 @regression을 적용하고, 추가 설계 검증과 결함 시연에는 @regression을 적용한다.
- 자동 후보 11개와 수동 후보 1개다. 데이터 반복 및 환경별 실제 실행 건수는 별도 집계한다.
- 재현한 결함은 trace와 known-issues에 연결한다. test.fail()은 확인된 결함에 적용한다.
- 사용자 리뷰에서 추가한 TC는 리뷰 추가로 표시한다.
### P1 관찰 결과

정상 공개 계정으로 Chromium PC(1280×720)와 Pixel 7 에뮬레이션에서 각각 새 컨텍스트로 로그인했다. 두 환경 모두 /inventory.html로 이동했고 Products 제목과 6개 상품을 확인했다. TC-LGN-002는 URL·제목·목록 표시를 검증한다. 사용자 P1 진행 승인에 따라 해당 TC를 구현하며, 다른 기능 TC는 관찰·리뷰 대기다. 비밀번호는 로컬 .env에서만 읽는다.

### P2 구현 제안과 리뷰 항목

- 위 7개 TC를 자동화한다. 핵심 구매 경로에는 @smoke와 @regression, 나머지는 @regression을 적용한다.
- TC-CHK-003은 필드 3개를 데이터 주도 반복으로 검증한다. 각 실행은 독립 상태에서 시작한다.
- 금액은 소수 오차를 피하도록 센트 정수로 계산한다. $3.20은 관찰한 상품 조합의 기준값으로 기록한다. 8% 및 일반 반올림 규칙은 별도 요구 근거가 확정되면 확대한다.
- 테스트 데이터는 test-data의 상품·주문 데이터로 관리하고, 사이트 조작은 InventoryPage·CartPage·CheckoutPage에 둔다.
- 상품 상세·정렬 테스트 중 상세 정합성은 P2에 포함하고 정렬은 P3에서 다룬다.
- P2 7개 TC는 사용자 승인 후 구현했다. P0·P1을 포함한 TC ID는 9개이며 필수 입력 3개 반복을 적용해 환경당 11건, PC·모바일 합계 22건이 통과했다.

정렬 초기 기준과 동률 상품 보존 조건은 관찰 데이터를 바탕으로 추가한 AI 설계 제안이며 사용자 리뷰 대상이다.

- TC-INV-002는 정렬 옵션 4개를 각각 독립 테스트로 실행한다.
- TC-REG-001은 standard_user와 problem_user를 같은 테스트 절차로 비교한다. 정상 계정은 Pass, 확인된 결함 계정은 test.fail()과 KI-001 annotation으로 표시한다.
- 기대 결과는 정상 입력 유지와 주문 요약 진입으로 둔다. 오류가 나는 현상을 성공 조건으로 바꾸지 않는다.
- 문제 계정에서 예상과 다른 단계의 실패를 정상적인 기대 실패로 처리하지 않도록, 입력 유지 단언 직전까지 사전 조건을 확인하고 알려진 필드 오동작을 확인한 경우에만 기대 실패를 표시한다. 오류 단계는 KI-001과 함께 점검한다.
- TC-REG-002 수동 시각 확인은 후속 수동 검토 대상으로 유지한다.
- P3 2개 TC는 사용자 리뷰 승인 후 구현했다. 정렬 4종과 계정 2종을 각각 독립 실행한다.
### P3 자동화 결과

전체 자동 TC ID는 11개다. 정렬 4종·필수 입력 3종·계정 2종 반복을 적용해 환경당 17건, PC·모바일 전체 34건을 실행했다. 일반 통과 32건과 KI-001 기대 실패 2건으로 예상 밖 실패·재시도 없이 완료했다. Playwright의 전체 성공 집계에는 기대 실패도 포함된다. 수동 TC-REG-002는 아직 수행 전이다.

확인된 필드 오동작과 오류 화면을 검증한 뒤에만 기대 실패를 표시한다. 다른 증상의 실패는 일반 실패로 남고, 결함이 사라지면 정상 기대 결과를 검증해 통과한다. 이 경우 known-issues 상태를 재검토한다.
